# The three charts — what each one shows, and what was decided to draw it

Built by `analysis/figures.py`. Regenerate all three with:

```
python analysis/figures.py
```

That command re-scores every committed extract under `runs/` against every
`data/sim/seed*/ground_truth.json`, rewrites `analysis/out/metrics_long.csv`
and `analysis/out/summary.md`, and redraws the three PNGs. No *plotted* value
is typed by hand — but some caption text is, and that distinction matters, so
here is exactly where each number comes from:

- **Every ROI, error, coverage and width value** comes from
  `scoring.run_scoring()` — the same pre-registered harness that writes
  `analysis/out/summary.md`. The figures call it; they do not re-implement it.
- **The response curves in figure 2** are read straight from the committed
  result JSONs and interpolated onto the ground-truth multiplier grid. The
  scorer only evaluates two points (0.5x, 1.0x); the rest of each curve is
  plotted from the same JSON field the scorer reads.
- **Two derived numbers are computed inside `figures.py` and nowhere else:**
  the channel ordering, from `simulation.checks.channel_snr` (the C7 gate's own
  function), and Robyn's portfolio-level ROI anchor in figure 1. Both are
  visible in the script's stdout when it runs.

- **The caption prose is hand-maintained, and it contains numbers.** The
  divergence counts (64, 122, 1-6), the sampler specs (2000/2000, 500/500,
  1000/1000), the Robyn run specs (4000x5, 2000x5), L3's 92% coverage, the
  tv-curve figures (2.4x the truth at 0.25x, 1.16x at 0.5x, the crossing
  between 0.5x and 0.75x, the +0.1% Robyn graze) and the 1.25x-1.5x ooh
  crossing are string literals in `figures.py`. So are the tool versions in the
  legends ("Meridian 1.8.0", "Robyn 3.12.1"), the scenario line every caption
  carries ("8 geos x 156 weeks, generator 1.0.0, 5 seeds") and Robyn's "3 of
  its 5 seeds fail its own convergence check". The versions and the seed count
  are the two most likely to move. **This list is meant to be exhaustive: if
  you put a number in a caption, add it here.** They were read
  off the committed run JSONs and the committed `summary.md`, but they will
  **not** move on their own if a run is ever re-exported. Anyone changing a
  run must re-check those literals; nothing in the pipeline will catch a stale
  one.

`analysis/out/summary.md` is committed and is the artifact to quote.
`analysis/out/metrics_long.csv` is regenerated by that same command but is
**gitignored** — it is a local intermediate, not a published source, so no
number in these charts or in `analysis/ORACLE.md` should rest on it alone. The
per-channel absolute errors those documents quote are printed in
`summary.md` for exactly that reason.

Every caption states, on the figure itself and above the fold, that the data
are simulated. That is not a disclaimer to be moved to a footnote: a chart of
ROI per channel is exactly the kind of image that gets screenshotted without
its context.

## Decisions

**D-F1 — National arm only, in figures 1 and 2.** Meridian ran both a national
and a geo arm; Robyn and the national oracle rungs ran national only. Putting
Meridian's geo numbers in the same column as everyone else's national numbers
would compare different denominators — the exact error the adversarial audit
caught in an earlier draft of `analysis/ORACLE.md`. The geo runs appear in
figure 3, in their own labelled block, never averaged in with national.

**D-F2 — The oracle series is L3, not L2.** L2 is handed the true baseline; L3
estimates its own (intercept + linear trend + 3 annual Fourier harmonics +
observed control), exactly as both tools must. Showing L2 next to the tools
would hand the oracle an advantage neither tool ever gets, and a fair reader
would discount the whole comparison. L2 stays in figure 3, where the point
being made is about intervals rather than about a like-for-like race.

This is deliberately *not* the rung `analysis/ORACLE.md`'s per-channel table
uses, and the two documents are not in conflict — they answer different
questions. ORACLE.md asks a ceiling question ("was this channel recoverable by
anybody?"), and giving that rung the true baseline removes one more excuse.
These charts run a race, and a race needs both sides under the same handicap.
The gap is real and worth knowing when reading across the two: on tv, search
and social the L2 errors are 0.04 / 0.15 / 0.24 and the L3 errors are 0.10 /
0.32 / 0.38. Both are far inside the tools' 0.34–0.79, which is why the finding
survives either choice — but a sentence quoting an oracle number has to say
which rung it came from.

The cost of that choice is honest and visible: L3's error on display is 1.22,
worse than either tool's, because a channel with a signal-to-noise of 0.10
takes the estimated baseline's noise on top of its own. Figure 1 does not hide
that dot.

**D-F3 — Channels ordered by signal-to-noise, with the C7 floor drawn.** The
whole finding is that recoverability is per channel. Ordering alphabetically,
or by spend, would bury it. `analysis/figures.py` imports
`simulation.checks.channel_snr` — the same function the C7 gate uses — so the
chart and the gate can never drift apart. The shaded region to the right of
the divider is where the oracle fails too.

**D-F4 — Each tool's reference level is drawn, for both tools.** Figure 1
carries two dotted horizontal lines: Meridian's default ROI-prior median
(e^0.2 ≈ 1.22, from `meridian/model/prior_distribution.py`) and Robyn's own
portfolio-level ROI — the single number an equal-effect-per-spend
decomposition implies, computed from Robyn's own point estimates and its own
spend (0.70, mean over the five seeds). Drawing one tool's line and not the
other's would read as a thumb on the scale. Both are computed in the script;
neither is typed in.

**The two lines do not mean the same thing, and the chart should not be read
as if they did.** Robyn's 0.70 really is where its estimates sit: its five
channel ROIs span 0.68 to 0.73, a factor of 1.08 against a truth that spans
4.4. Meridian's 1.22 is the *top* of its band, not its centre — its estimates
run 0.74 to 1.24, so the prior median marks where its over-estimated channels
land (ooh 1.24 against a true 0.8), while the channels it under-estimates fall
well below it (social 0.76 against a true 2.5). "Meridian collapses to its
prior median" would be the easy caption and it is not what these five seeds
show; what they show is compression, with the prior median as its ceiling.

**D-F5 — Every seed is a dot; no error bars in figure 1.** Five seeds is too
few for a standard error to mean much, and a bar would imply a sampling model
this design does not have. The dots plus the mean tick say what there is to
say. Runs that failed their tool's own convergence check are drawn hollow, so
a reader can see at a glance which points Robyn declines to endorse.

**D-F6 — Robyn's interval bar is hatched in figure 3.** Robyn's reported
interval is the spread across Pareto-front candidate models. It is not a
posterior interval and was never meant to be a 90% interval, so its 0.16
coverage is not a calibration failure of the same kind as Meridian's 0.60.
Plotting it as an unmarked bar next to two genuine 90% intervals would be the
single most misleading thing this figure could do. It is hatched, its kind is
printed in the row label, and the caption says so.

## The figures

### `fig1_roi_per_channel.png` — estimated vs true ROI per channel

The money chart. One dot per seed per estimator, the true ROI as a black rule,
channels ordered by signal-to-noise. What it shows: for tv, search and social
the oracle comes closer to the truth than either tool does — its errors are
0.10 / 0.32 / 0.38 against the tools' 0.34 to 0.79 — so there the failure
belongs to the tools. For ooh and display the oracle misses too, and the tools'
apparently better numbers there are not a measurement: 0.8 and 1.2 are simply
the only two true ROIs that land inside or beside the narrow bands both tools
compress everything into, while tv, social and search sit far outside them.

Without the oracle series this chart is a tie: 0.533 mean absolute error for
Meridian against 0.555 for Robyn. With it, the tie stops being the result.

### `fig2_response_curves.png` — estimated vs true response curves

Mean curve over the five seeds, band = seed-to-seed range, evaluated on the
generator's own multiplier grid (0 to 3x observed spend); the scorer's fixed
evaluation points, 0.5x and 1.0x, are marked. The oracle is dashed and drawn
last so that where it lies on top of the truth — tv, social — you can still
see it.

**The two tools' curves are not equally native, and the caption says so.**
Meridian's come from its own `incremental_outcome` counterfactual. Robyn has no
equivalent — it cannot be asked "scale the whole spend series" — so its curves
are **reconstructed by this repo** from the selected model's own fitted
parameters (θ adstock, Hill α/γ, coefficient), per `runs/robyn/DECISIONS.md`
RD9. The reconstruction is not free-floating: the export aborts unless it
matches Robyn's own `xDecompAgg` at 1.0x within 1%. It is still our arithmetic
on Robyn's parameters rather than Robyn's own output, and that asymmetry
belongs on the chart, not only in a decision log.

What it shows: on tv, search and social — the three channels this dataset can
measure — both tools are wrong across the whole budget range, not just at the
observed point, which is what makes them wrong for the budget question people
actually ask them. "Wrong" is not the same as "too low", and the panels say so.
Of the plotted means: Robyn's sits below the truth everywhere on all three,
while Meridian's sits below on search and social but *over-states* tv up to
0.5x spend — 2.4x the truth at 0.25x, 1.16x at 0.5x — crossing under between
0.5x and 0.75x. On ooh and display both wander: Robyn's mean ooh curve crosses
the truth between 1.25x and 1.5x.

Those statements are about the **mean** curve, which is the line drawn; the
band around it is the seed-to-seed range and it does not obey them. Every one
of Meridian's five seeds is above the truth on tv at 0.25x, and one Robyn seed
(103) grazes the truth there too, at +0.1%. On search and social no seed of
either tool is above the truth anywhere on the grid. A claim of the form "the
tool is always below" has to name whether it is about the line or the band,
and this one is about the line. The chart's title is scoped to the measurable channels for that reason —
"wrong at every budget" is true where it is claimed and would be false if
claimed for all five.

### `fig3_intervals.png` — interval coverage and width

Coverage (share of channel-seed intervals containing the true ROI) against
mean width relative to true ROI, for all seven tool-arms, national block above
and geo block below. Non-convergence counts are printed in the row labels, and
so is Meridian's geo sampler escalation — that arm shipped at 2000/2000
adapt/burnin, its third attempt, with 64 and 122 divergent transitions, while
its national arm needed no escalation. Robyn's escalation is disclosed on every
chart; Meridian's has to be too, or the pre-registration is only being enforced
against one tool.

The width panel is the one place in the whole deliverable where Robyn's bar
being the smallest could read as favourable, and a reader skimming could take
it as Robyn being the more precise tool. (Its coverage bar is the smallest of
the seven too — there, small is plainly bad, so nobody misreads it.) It is not: a narrow spread across shortlisted candidate models is
not a confident posterior, and the caption says so in the same breath as the
coverage caveat rather than leaving the width uncaveated.

What it shows: L3, on the same data and estimating its own baseline, covers
92% against a nominal 90%. "The data were hard" does not explain Meridian's
60%. Robyn's 16% is marked as the different kind of quantity it is.

## What these charts cannot tell you

They describe one simulated scenario with exogenous spend, five seeds, one
version of each tool, and one pre-registered setup per tool — the generosities
of which are listed in `runs/*/DECISIONS.md`. They are not evidence about how
either tool behaves on other scenarios, on endogenous spend, or on real data.
The full list of what this project does and does not license lives in
`analysis/ORACLE.md`.
